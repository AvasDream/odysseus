Assumptions made

AssumptionRationale
The mcp python client honors AsyncExitStack.aclose() to terminate the spawned stdio subprocess.If it leaks pipes/zombies internally, that is an upstream-library issue, not Odysseus code.
session.call_tool() on a hung/malicious MCP server can block indefinitely (no timeout in _do_call, mcp_manager.py:476-502).Per THREAT_MODEL, MCP servers are admin-added/trusted; a hung call stalls only one cancellable agent turn — robustness, not security.
Auto-reconnect-then-retry for builtin servers (mcp_manager.py:454-469) can re-run a non-idempotent builtin tool (e.g. bash) if the subprocess dies after a side effect.bash/python are admin-only and admin-intended — robustness nit, not a privilege/injection bug.
build_chat_context (chat_processor.py) produces the message list passed into the agent loop.So the UNTRUSTED_CONTEXT_POLICY system preamble is present for native-path tool results.
