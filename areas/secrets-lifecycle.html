Findings

HuggingFace token written in plaintext into world-readable /tmp wrapper scripts (chmod 0o755)Medium real

Confidence
Confirmed by trace. Preconditions: POSIX host (safe_chmod no-ops on Windows); admin invokes POST /api/model/download or the serve action with req.hf_token set or a stored HF token present, backend != ollama (ollama forces hf_token=""); a second non-app local OS user (or any process able to read /tmp) reads /tmp/odysseus-tmux/<session>.sh during the live window.
Location
routes/cookbook_routes.py:523, 550, 681, 801-802, 1484, 1813-1816; routes/shell_routes.py:399 (TMUX_LOG_DIR); routes/cookbook_routes.py:521, 273-274 (token source)
Invariant violated
Secrets (HF_TOKEN) must never be persisted to a path readable by other local/unprivileged users. The codebase enforces this everywhere else — .app_key, vault.json, integrations.json are all chmod 0o600, and vault_routes.py explicitly defends against ps//proc/<pid>/cmdline reads "by any local user." A 0o755 script in shared sticky /tmp is an inconsistent violation.
Why it matters
Any unprivileged local user (or any process able to read /tmp) can read the admin's HuggingFace token, granting access to the admin's gated HF repos. The download-path self-rm is appended inside the script AFTER the up-to-10x retry/sleep download loop, so it only fires on completion — persisting during the multi-hour download and on crash/kill/tmux-kill. The serve path (write ~1813, chmod ~1816) has NO self-rm at all and lives for the entire serve lifetime and afterward.
Trigger
Admin triggers POST /api/model/download or the serve action with an HF token. The wrapper /tmp/odysseus-tmux/<session>.sh is written containing export HF_TOKEN='<token>' then chmod 0o755; TMUX_LOG_DIR is created with default umask and never mode-restricted. Exploitable by: a co-resident local OS user on the same single host.
Fix direction
Create TMUX_LOG_DIR with mode 0o700 and chmod secret-bearing wrapper/runner scripts to 0o600 (POSIX) instead of 0o755; or pass HF_TOKEN to the child via an env file / tmux send-keys rather than baking it into a persistent on-disk script. The remote runner local temp copy (line ~763) needs the same restriction before scp.

Assumptions

  • tempfile.gettempdir() resolves to a shared, world-traversable /tmp on typical POSIX deployments; on a hardened per-user TMPDIR exposure narrows but explicit chmod 0o755 still over-shares.
  • _bash_squote only shell-escapes the token value; it does not encrypt/protect it on disk.
  • httpx RequestError/HTTPStatusError str() can include the request URL (standard httpx behavior).
  • Single-host threat model treats other local unprivileged users as adversary for secret-on-disk/argv exposure — inferred from vault_routes.py comments.
